About me

What I do, and how I work.

I build websites that are fast, responsive and genuinely pleasant to use — from a single landing page to a full WordPress site.

My day-to-day is HTML, CSS and JavaScript for custom front-end work, and WordPress when a client needs to manage their own content. I also build with AI assistance, which mostly means I can move through layout exploration, copy drafts and boilerplate quickly, and spend the saved time on the parts that actually need judgement: structure, performance, and how the thing feels to click through.

I care about the details that clients notice without naming them — spacing that holds up on a phone, buttons that respond, pages that load before anyone gets bored.

Skills

The tools I reach for on a build.

HTML5 & semantic markup

Clean, accessible document structure — the part that decides whether a site is readable by people, screen readers and search engines alike.

CSS3

Responsive layouts with Grid and Flexbox, custom properties, transitions and 3D transforms — like the scene at the top of this page.

JavaScript

Vanilla JS for interaction — menus, scroll behaviour, form handling and UI state, without dragging a framework into a static site.

WordPress

Theme setup, plugins and page builders for clients who need to edit their own content after launch — without calling a developer.

Git & GitHub Pages

Version control and static hosting — projects live in a repository and deploy straight from it, like this portfolio does.

AI-assisted web development

Using AI tools inside the build process — layout exploration, content drafting, boilerplate and debugging — then reviewing and finishing every line by hand. It's how a small team ships at the pace of a bigger one.

My process

Four steps, from first call to live site.

  1. 1

    Planning

    We agree what the site needs to do, who it's for, and what pages and content it takes to get there.

  2. 2

    Design

    Layout, type and colour come together into a direction you can see and react to before anything gets built.

  3. 3

    Development

    The design gets built properly — responsive across devices, accessible, and quick to load.

  4. 4

    Launch

    Final checks, then the site goes live. You get the files and a walkthrough of how to update it.
